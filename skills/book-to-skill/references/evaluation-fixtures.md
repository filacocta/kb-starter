# Behavior evaluation

Choose realistic tasks before tuning the candidate. Include an intended task,
an adjacent request that should not activate it, a source-disagreement case and
an authority boundary relevant to the operation. Test useful output against
real artifacts, not headings or wording copied from the skill.

Compare the existing workflow and candidate using equivalent evidence. Record
commands, input revisions, outputs, failures and uncertainty. An independent
forward test adds confidence for complex or consequential procedures. It does
not replace deterministic validation. Do not promote a package whose observed
behavior still depends on unsupported tools or unauthorized side effects.
