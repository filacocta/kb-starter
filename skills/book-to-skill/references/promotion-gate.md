# Promotion decision

Promote only when a recurring task has precise triggers, source-backed procedures,
a useful output and evidence of improvement on real tasks. Inspect package files,
referenced resources, scripts, permissions and provenance. Account for source
disagreement and limitations. Validate with the runtime's skill-creator checker.

Choose synthesis if knowledge is the product, a deterministic helper for mechanical
work, or a candidate skill for repeatable judgment. Existing capability may make
a new package redundant. A local candidate is not installed or generally portable
merely because validation succeeds. Record the actual eval and release decision.
