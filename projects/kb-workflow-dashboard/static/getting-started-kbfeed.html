kb-feed / Telegram capture

Capture from your phone. kb-feed routes it into the KB queues.

kb-feed is a systemd --user daemon that watches a private Telegram supergroup. Each message lands in a KB queue based on which topic thread it was posted in. It only ever writes the queue files (author: kb-bot), never fetches URLs, and leaves ingestion to the normal KB workflow.

Day to day 1. Post a URL in its topic thread → bot replies Queued with an Undo button. 2. Wrong thread? Tap Undo (or reply /kbundo) before the 2-minute flush. 3. No topic yet? Use the unfiltered thread. Broad idea? inspiration-capture. 4. Monday 10:00 the weekly digest DMs you proposals — /kbreply ....

How a message becomes a queue item

Capture is recoverable at every step: intake to SQLite, then a separate flush writes markdown under the shared write lock with an optional kb-bot git commit. Nothing is fetched.

1 intakeTelegram pollLong-polls the bot. Filters by allowed chat + user, reads message_thread_id, extracts & validates URLs (public http(s) only).
2 queueSQLite outboxRow enqueued to outbox (URLs) or capture_outbox (text), deduped against seen_urls. Undo cancels pending rows.
3 flushWriter (every 2 min)Claims pending rows, appends to KB markdown under .kb-write.lock, marks written, optionally commits as kb-bot.
4 queuesKB markdownLands in the right queue file with a (via Telegram #thread, date) annotation.
5 reviewYou / weekly digestPromote, ingest, or triage through the normal KB workflow. kb-feed never ingests on its own.

The five lanes

The destination is decided entirely by which thread you post in (its topic_map slug) and whether the message carries a URL. Two slugs are reserved: unfiltered and inspiration-capture.

You post…in a thread mapped to…Lands in
A URLa normal topic (e.g. rockhounding)topics/<slug>/reading-list.md under ## Pending — or ## Auto-approved if that lane sets auto_approve = true.
Text, no URLa normal topictopics/<slug>/research-ideas.md — a prose rabbit hole / project seed. Not a fetched source.
A URLunfilteredreadinglist/Links.md, the global URL inbox — triage to a topic later.
Textinspiration-capturereadinglist/topics.md, the broad topic-interest inbox.
Anythingan unmapped threadNothing is written. The bot replies asking you to map the thread first (lossless — no silent drops).

Setup essentials

One-time per machine. Full operator guide: ~/Vault/projects/kb-feed/README.md.

  1. Create a private supergroup, enable Topics, add the bot as admin. Token goes in ~/.config/kb-feed/credentials.env (TELEGRAM_BOT_TOKEN, chmod 600).
  2. Set allowed_chat_id and allowed_users in ~/.config/kb-feed/kb-feed.toml. Capture requires both allowlists.
  3. Map each thread to a KB topic slug: post map <slug> in the thread to learn its id, then kb-feed topic-map set <thread_id> <slug>. Also map one thread each to unfiltered and inspiration-capture.
  4. Do one manual live flush and inspect the git diff before enabling timers: kb-feed outbox flush --kb-root ~/Vault/knowledgebase --allow-live-kb --commit --commit-debounce-seconds 0.
  5. Enable services: systemctl --user enable --now kb-feed-poll.service kb-feed-flush.timer. Optional weekly review: kb-feed-digest-weekly.timer + kb-feed-digest-reminder.timer.

Boundaries & safety

These keep kb-feed from ever becoming an unsafe writer.

allowlist

Two explicit gates

State-changing capture needs both allowed_chat_id (one chat) and allowed_users (per-user IDs).

URL safety

Public http(s) only

Rejects non-http(s) and DNS pointing at private, loopback, carrier-NAT, or cloud-metadata addresses.

authorship

kb-bot guard

Appends fail if the target file lacks author: kb-bot. The non-negotiable backstop (Rule 1).

live gate

--allow-live-kb

Any command that could touch ~/Vault/knowledgebase refuses unless the live flag is explicit.

no fetching

Strings only

kb-feed never fetches a URL. Capture, triage, and digest reason from URL strings and notes only.

generated

Dive-queue is read-only

kb-feed writes only the queue files and regenerates _dive-queue.md read-only — it never appends to it (Rule 13).
