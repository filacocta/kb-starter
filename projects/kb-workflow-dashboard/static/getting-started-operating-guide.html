Book Or Source Cluster To Skill

A skill is a tested workflow artifact. The KB remains the source of truth for custody, synthesis, fixtures, lifecycle, and install decisions.

custody Raw source exists Store books and long PDFs under _library/; keep raw files out of public repos.
topic Relevant excerpts Create topic source notes only for the sections actually used by that topic.
model Practice model Synthesize procedures, critique criteria, examples, failure modes, and boundaries.
gate Candidate note Record trigger, repeatability, scope, provenance, blockers, and next action.
eval Real fixtures Test trigger behavior and output quality against real artifacts before install.
package Skill package Draft SKILL.md plus references only after synthesis and fixtures exist.
decision Install or defer Install locally only after explicit approval. Starter-safe status is a separate decision.

Command Choice

Pick the smallest tool that matches the current state. Do not turn a read task into a write task.

NeedUseWrites?Result
Orient on a topic or project /kb-scan No Reads index, summaries, and relevant state before action.
Process one approved source /kb-ingest <url|path> Yes Creates one immutable source note and updates queue state.
Work through approved topic items /kb-queue <topic> Yes Processes approved queue items with checkpoint support.
Run unattended approved ingestion /kb-auto <topic> Yes Processes only URL-first or local-PDF lines under ## Auto-approved.
Turn source notes into wiki notes /kb-synthesise <topic> Yes Creates or updates concept, entity, and synthesis notes.
Evaluate a source cluster as a skill $book-to-skill Maybe Records lifecycle state and drafts a package only if the gate passes.
Close implementation or research work /kb-wrap Yes Records decisions, todos, summaries, log entries, and follow-ups.
Check structural health _tools/kb-lint.py --all No Reports frontmatter, links, queues, media, and authorship findings.
Change queue checkbox state _tools/kb-checkoff.py Yes Mutates queue lines under the shared write lock and regenerates derived views.
Capture a URL with provenance _tools/kb-capture-url.py <url> Yes Routes to a topic's ## Pending (--topic) or readinglist/Links.md, tagged by source. Also fired automatically by the WebFetch capture hook.
Diagnose kb-feed health kb-feed doctor No Reports thread→topic mappings, blind topics, dropped-message counters, queue backlog, and unapplied proposals.

Non-Negotiables

These rules prevent the dashboard from becoming a second, unsafe source of truth.

authorship

Only write kb-bot files

Existing Markdown without author: kb-bot is user-owned. Do not edit it.

approval

No blind fetching

Interactive fetches need approval. Headless fetches must come from ## Auto-approved.

queues

Use shared tools

Queue mutation belongs in _tools/kb-checkoff.py, not direct dashboard edits.

generated

Generated views are read-only

_dive-queue.md summarizes other files (topic ## Auto-approved + research-ideas.md). Write to those, never to the generated view.

ladder

One section ladder

Reading lists use only ## Pending → ## Approved → ## Auto-approved → ## Processed → ## Failed — Retry. kb-lint.py rejects any other ingestion heading; sub-group with ###.

checkpoint

Long writes need a checkpoint

Multi-file KB operations should be resumable before the first durable write happens.

skills

Synthesis before skills

Books and source clusters become skills only after a repeatable task, fixtures, and install decision exist.
